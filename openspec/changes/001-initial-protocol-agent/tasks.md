# Implementation Tasks: Командный план реализации

Проект: **«Агент: ИИ система для протоколирования совещаний Министерства образования»**  
Состав команды: **5 человек** (включая тимлида).  
Контрольные вехи:
- **Декабрь 2026:** Тестовая версия (Alpha / MVP) для опытной эксплуатации;
- **Февраль 2027:** Готовая промышленная версия (Release / Финал) с развёртыванием в защищённом контуре.

---

## Матрица ролей команды

| Роль | Основная зона ответственности | Ключевые компетенции |
|---|---|---|
| **1. Team Lead / System Architect & PM** | Общая системная архитектура, требования ИБ защищенного контура, интеграция модулей, управление сроками и рисками, ведение OpenSpec | Python, System Design, Information Security, Project Management |
| **2. AI / ML Engineer (Speech & Local LLM)** | Офлайн STT аудиопайплайн (1.5 ч), адаптация словаря Минобразования, квантизация и локальный инференс российской LLM (GigaChat / Saiga / Vikhr) | PyTorch, faster-whisper, GigaAM, vLLM / llama.cpp, Audio DSP |
| **3. Backend Engineer (NER, RAG, DOCX)** | Бизнес-логика FastAPI, пайплайны извлечения сущностей, резолюция ФИО и сроков, аналитика рисков/противоречий, генерация .docx | Python, FastAPI, Pydantic, python-docx, docxtpl, LangChain / LlamaIndex |
| **4. Frontend / Fullstack Developer** | Клиентское веб-приложение, загрузчик файлов, интерактивный редактор протокола, панель аналитики, счётчик циклов правок (до 2) | React, TypeScript, Vite, Tailwind CSS, State Management, REST API |
| **5. QA Engineer / AI Evaluator & TechWriter** | Оценка метрик качества LLM (полнота, точность, галлюцинации), синтез и разметка тестовых датасетов, сквозное тестирование, инструкция пользователя | Python (pytest, DeepEval / Ragas), Prompt Evaluation, Technical Documentation |

## Декомпозиция задач по ролям и спринтам

### Этап 1: Архитектурный каркас и исследовательские PoC (Октябрь – Ноябрь 2026)

#### [TL] Team Lead / Architect
- [ ] **TL-101: Формализация спецификаций и архитектурного профиля OpenSpec** `P0`
  - *Описание:* Фиксация базовых спецификаций в репозитории, определение форматов обмена данными между STT, LLM и генератором DOCX.
  - *DoD:* Директория `openspec/` содержит валидные спецификации; схемы Pydantic согласованы с бэкендом и фронтендом.
- [ ] **TL-102: Проектирование профиля изоляции и локального развёртывания** `P0`
  - *Описание:* Разработка конфигурации изолированного запуска без выхода во внешние облака (локальный docker-compose или скрипты для рабочей станции).
  - *DoD:* Документированы требования к аппаратному обеспечению ПК (GPU/CPU, RAM, диск); проверен запуск в offline-режиме.

#### [ML] AI / ML Engineer (Speech & Local LLM)
- [ ] **ML-101: Развёртывание и бенчмарк автономного STT для длинных аудио (1–1.5 ч)** `P0`
  - *Описание:* Сравнение и настройка `faster-whisper` и `GigaAM-v2` для распознавания русской речи совещаний с чанкованием.
  - *DoD:* Аудиозапись 90 минут транскрибируется без падений по OOM; точность по WER/CER на русском языке удовлетворяет требованиям; формируются таймкоды.
- [ ] **ML-102: Настройка доменного словаря и hotwords для распознавания речи** `P1`
  - *Описание:* Механизм передачи контекстных подсказок (список сотрудников, аббревиатуры Минобразования) в STT.
  - *DoD:* Имена руководителей и аббревиатуры (ОГЭ, ЕГЭ, ИРО) корректно транскрибируются в тестовых аудиодорожках.
- [ ] **ML-103: Подготовка локального инференса российской LLM** `P0`
  - *Описание:* Развёртывание локального окружения с российской моделью (GigaChat On-Prem SDK либо локальная квантованная Saiga/Vikhr через llama.cpp/vLLM).
  - *DoD:* Проверен локальный инференс без обращения к внешним незащищенным API; зафиксирован latency на тестовых промптах.

#### [BE] Backend Engineer (NER, RAG, DOCX)
- [ ] **BE-101: Каркас FastAPI сервиса и управление рабочими сессиями** `P0`
  - *Описание:* Реализация REST API для создания сессии, загрузки файлов (аудио, повестка, участники, шаблон, архив) и хранения состояния.
  - *DoD:* Эндпоинты `POST /api/sessions/upload` и `GET /api/sessions/{id}/status` возвращают корректные статусы; файлы сохраняются в локальном хранилище.
- [ ] **BE-102: Шаблонизатор и генератор официального протокола (.docx)** `P0`
  - *Описание:* Модуль сборки Word-документа на `docxtpl` по утверждённому бланку Министерства образования.
  - *DoD:* Из тестового JSON генерируется файл `.docx`, полностью идентичный официальному бланку (шрифты Times New Roman, межстрочные интервалы, таблицы поручений).
- [ ] **BE-103: Парсер сопутствующих документов (повестка, список участников, архив)** `P1`
  - *Описание:* Извлечение текста и списков из входных файлов Word/PDF/TXT для обогащения контекста модели.
  - *DoD:* Из повестки извлекаются пункты тем, из списка участников — ФИО и должности для автодополнения.

#### [FE] Frontend / Fullstack Developer
- [ ] **FE-101: Инициализация SPA-клиента и модуль пакетной загрузки материалов** `P0`
  - *Описание:* Создание интерфейса на React + Vite + Tailwind: drag-and-drop форма для аудиозаписи и 4 типов сопроводительных документов.
  - *DoD:* Пользователь видит валидацию форматов, прогресс загрузки и индикатор ожидания расшифровки/генерации.
- [ ] **FE-102: Проектирование UI состояния рабочей сессии** `P1`
  - *Описание:* Организация клиентского состояния (Zustand/Redux) для хранения черновика протокола, списка участников и аналитических пометок.
  - *DoD:* При перезагрузке страницы состояние сессии восстанавливается из локального кэша/API.

#### [QA] QA Engineer / AI Evaluator & TechWriter
- [ ] **QA-101: Формирование тестового датасета реальных и синтетических стенограмм** `P0`
  - *Описание:* Сбор эталонных пар: аудио/стенограмма $\leftrightarrow$ утверждённый протокол совещания.
  - *DoD:* Подготовлено не менее 5 размеченных сценариев с явными решениями, спорными моментами, пропущенными сроками и архивными протоколами.
- [ ] **QA-102: Разработка методики и скриптов оценки качества LLM (Evaluation Benchmark)** `P0`
  - *Описание:* Метрики: Recall поручений, Precision дат, совпадение ответственных, детектор галлюцинаций (фактологическая точность).
  - *DoD:* Скрипт автоматизированной оценки выдает числовые метрики качества на эталонных данных.

### Этап 2: Интеграция пайплайнов и выпуск Тестовой версии (Декабрь 2026)

#### [BE] Backend Engineer
- [ ] **BE-201: Пайплайн извлечения решений, поручений, сроков и ответственных** `P0`
  - *Описание:* Промпт-инжиниринг и алгоритм структурирования: сопоставление стенограммы с повесткой, извлечение связок «Кто $\rightarrow$ Что $\rightarrow$ До какого числа».
  - *DoD:* Из стенограммы формируется валидный JSON проекта протокола; дискуссии без решения отсекаются.
- [ ] **BE-202: Модуль аналитики: поиск пробелов и противоречий (с архивом)** `P1`
  - *Описание:* Выявление поручений без срока (`MISSING_DUE_DATE`), без исполнителя и сравнение с предыдущими протоколами.
  - *DoD:* JSON ответа содержит блок `analytics` с перечнем конкретных замечаний и цитатами из стенограммы.
- [ ] **BE-203: Контроллер повторной генерации (до 2 циклов)** `P0`
  - *Описание:* Логика эндпоинта `POST /api/sessions/{id}/refine`: применение правок секретаря к проекту, счетчик циклов (1/2, 2/2) и переход в ручной режим при превышении.
  - *DoD:* Третья попытка автоматической регенерации возвращает блокировку эскалации с сохранением возможности ручной правки.

#### [FE] Frontend / Fullstack Developer
- [ ] **FE-201: Интерактивный редактор проекта протокола** `P0`
  - *Описание:* Визуальное редактирование: редактирование текста решений, инлайн-изменение сроков (datepicker) и выбор исполнителя из списка участников.
  - *DoD:* Секретарь может исправить любое поле в таблице поручений и сохранить изменения.
- [ ] **FE-202: Боковая панель аналитики и коллизий** `P1`
  - *Описание:* Отображение предупреждений об отсутствующих сроках/исполнителях и противоречиях с подсветкой соответствующих пунктов документа.
  - *DoD:* Клик по предупреждению подсвечивает проблемную строку в протоколе.
- [ ] **FE-203: Реализация счётчика кругов правок и режима ручной эскалации** `P0`
  - *Описание:* Индикатор «Круг 1 из 2», кнопка «Обновить через ИИ», при достижении лимита — блокировка и переход в ручную доработку.
  - *DoD:* Блок-схема правок из ТЗ полностью воспроизведена в интерфейсе.
- [ ] **FE-204: Экспорт и скачивание готового .docx документа** `P0`
  - *Описание:* Кнопка формирования и загрузки финального Word-файла.
  - *DoD:* Пользователь скачивает оформленный файл `.docx` в один клик.

#### [TL] Team Lead
- [ ] **TL-201: Сквозная интеграция компонентов и выпуск тестового релиза (Milestone Dec 2026)** `P0`
  - *Описание:* Интеграция Frontend, Backend, STT и локальной LLM в единый установочный пакет.
  - *DoD:* Проведено демонстрационное тестирование полного цикла на реальной аудиозаписи; сформирован проект протокола.

#### [QA] QA Engineer
- [ ] **QA-201: Комплексное тестирование тестовой версии (Alpha Testing)** `P0`
  - *Описание:* Прогон сквозных сценариев (E2E), нагрузочное тестирование на аудио 1.5 часа, проверка времени формирования документа (в пределах дня).
  - *DoD:* Оформлен отчёт о тестировании с перечнем выявленных дефектов и метриками точности.
- [ ] **QA-202: Подготовка черновика краткой пошаговой инструкции пользователя** `P1`
  - *Описание:* Руководство для сотрудника секретариата: загрузка, редактирование, выгрузка DOCX.
  - *DoD:* Документ с иллюстрациями и инструкцией по шагам.
